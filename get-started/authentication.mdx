NexCore uses API keys to authenticate every request made to the platform. Whether you are calling the REST API directly or using one of the official SDKs, you must include a valid API key with each request. Keys are scoped to a specific project, so a key issued for one project cannot access data belonging to another.

---

## Creating an API Key

Follow these steps to generate a new API key from the dashboard:

1. Open the [NexCore Dashboard](https://app.nexcore.io) and select your **Project**.
2. Navigate to **Settings → API Keys**.
3. Click **Create Key**.
4. Enter a descriptive name for the key (for example, `production-server` or `ci-pipeline`).
5. Select the appropriate [scope](#key-scopes) for the key's intended use.
6. Click **Create** and copy the key immediately — it is only shown once.

Your key will look like this:

```text
nxc_live_xxxxxxxxxxxxxx
```

Keys prefixed with `nxc_live_` are live (production) keys. Test environment keys use the prefix `nxc_test_`.

## Using Your API Key

### REST API

Pass your API key in the `Authorization` header of every HTTP request:

```http
Authorization: Bearer YOUR_API_KEY
```

Here is a complete example using `curl`:

```bash
curl --request GET \
  --url https://api.nexcore.io/v1/streams \
  --header "Authorization: Bearer nxc_live_xxxxxxxxxxxxxx" \
  --header "Content-Type: application/json"
```

### TypeScript SDK

When initialising the NexCore client, pass your key via the `apiKey` option. Use an environment variable so the key is never hardcoded in your source:

```typescript
import { NexCore } from "@nexcore/sdk";

const client = new NexCore({
  apiKey: process.env.NEXCORE_API_KEY,
});
```

## Key Scopes

Each API key is assigned a scope that controls what actions it is permitted to perform. Always issue keys with the minimum scope required for the task.

| Scope | Description | Use Case |
|---|---|---|
| `read` | Read-only access to streams, events, and analytics data | Dashboards, reporting tools, read-only integrations |
| `write` | Emit events and create or update streams | Application servers, data ingestion pipelines |
| `admin` | Full access including team management, billing, and key rotation | Internal tooling, CI/CD automation, infrastructure provisioning |

## Rotating Keys

You can rotate an API key at any time without downtime by following these steps:

1. Create a new key with the same scope as the key you want to replace (follow the [Creating an API Key](#creating-an-api-key) steps above).
2. Update your application's environment variables or secrets manager to use the new key.
3. Deploy your updated application and confirm it is authenticating successfully with the new key.
4. Return to **Settings → API Keys** in the dashboard, locate the old key, and click **Revoke**.

NexCore does not impose a grace period on revoked keys — a revoked key stops working immediately, so always confirm the new key is live before revoking the old one.

## Security Best Practices

<Warning>
  **Never commit API keys to source control.** If a key is accidentally pushed to a repository, revoke it immediately and issue a replacement.
</Warning>

Follow these practices to keep your API keys secure:

- **Use environment variables.** Store keys in environment variables and read them at runtime rather than hardcoding them in your source code:

  ```typescript
  const client = new NexCore({
    apiKey: process.env.NEXCORE_API_KEY,
  });
  ```

- **Use a secrets manager in production.** In cloud environments, use a dedicated secrets manager such as AWS Secrets Manager, Google Cloud Secret Manager, or HashiCorp Vault instead of plain environment variables.

- **Scope keys to the minimum required permissions.** A key used only to emit events should have the `write` scope — not `admin`.

- **Rotate keys periodically.** Establish a routine rotation schedule (for example, every 90 days) to limit the blast radius of any potential key exposure.

- **Add your `.env` file to `.gitignore`** so local environment files are never accidentally committed:

  ```bash
  echo ".env" >> .gitignore
  ```

## Error Codes

| HTTP Status | Error | Cause |
|---|---|---|
| `401 Unauthorized` | Missing or invalid API key | The `Authorization` header is absent, malformed, or contains a revoked key |
| `403 Forbidden` | Insufficient scope | The key is valid but does not have the required scope for the requested operation |

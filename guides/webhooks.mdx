NexCore webhooks push event data to your HTTP endpoints the moment they occur in your streams — no polling required. As soon as NexCore detects a matching event, it serialises the payload and delivers it to every registered endpoint that subscribes to that event type.

## Creating a Webhook

<Steps>
  <Step title="Open the Webhooks dashboard">
    In the [NexCore Dashboard](https://app.nexcore.io), navigate to **Project → Webhooks**, then click **Add Webhook**.
  </Step>
  <Step title="Enter your endpoint URL">
    Provide the full HTTPS URL of the endpoint that will receive webhook deliveries, for example `https://api.yourapp.com/hooks/nexcore`. The endpoint must be publicly reachable and respond to `POST` requests.
  </Step>
  <Step title="Choose a stream and event types">
    Select the stream you want to monitor from the **Stream** dropdown, then tick each event type you want to subscribe to — for example `user.signup`, `payment.completed`, or `stream.error`. You can subscribe to all events on a stream by selecting **Wildcard (\*)**.
  </Step>
  <Step title="Set a signing secret">
    Enter a long, random string as your **Secret**. NexCore uses this value to produce an HMAC-SHA256 signature that is attached to every delivery in the `X-NexCore-Signature` header. Store the secret in your application's environment variables so you can verify signatures at runtime.
  </Step>
  <Step title="Save and send a test delivery">
    Click **Save Webhook**. NexCore immediately sends a `webhook.test` event to your endpoint so you can confirm connectivity. Check the **Logs** tab to see the delivery status and your server's response.
  </Step>
</Steps>

## Webhook Payload

Every delivery is an HTTP `POST` request with `Content-Type: application/json`. The request body follows a consistent envelope format regardless of event type:

```json
{
  "id": "evt_01HZXXXXX",
  "type": "user.signup",
  "stream": "my-stream",
  "timestamp": "2024-09-15T12:34:56Z",
  "payload": {
    "userId": "42",
    "email": "user@example.com"
  }
}
```

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Globally unique event identifier. Use this to deduplicate retried deliveries. |
| `type` | `string` | Dot-separated event type that triggered the webhook. |
| `stream` | `string` | The name of the NexCore stream the event belongs to. |
| `timestamp` | `string` | ISO 8601 UTC timestamp of when the event was recorded in the stream. |
| `payload` | `object` | Arbitrary event data emitted by your producer. |

## Signature Verification

NexCore signs every delivery by computing `HMAC-SHA256(secret, rawRequestBody)` and sending the hex-encoded digest in the `X-NexCore-Signature` header. You should always validate this signature before processing a delivery.

<Warning>
Always verify the `X-NexCore-Signature` header in production before trusting or acting on any webhook payload. Skipping this step exposes your endpoint to spoofed requests from third parties.
</Warning>

### Node.js

```typescript
import crypto from "crypto";
import { IncomingMessage, ServerResponse } from "http";

const WEBHOOK_SECRET = process.env.NEXCORE_WEBHOOK_SECRET!;

export function verifySignature(req: IncomingMessage, rawBody: Buffer): boolean {
  const signature = req.headers["x-nexcore-signature"] as string | undefined;
  if (!signature) return false;

  const expected = crypto
    .createHmac("sha256", WEBHOOK_SECRET)
    .update(rawBody)
    .digest("hex");

  // Use timingSafeEqual to prevent timing attacks
  return crypto.timingSafeEqual(
    Buffer.from(signature, "hex"),
    Buffer.from(expected, "hex")
  );
}

// Express example
app.post("/hooks/nexcore", express.raw({ type: "application/json" }), (req, res) => {
  if (!verifySignature(req, req.body)) {
    return res.status(401).json({ error: "Invalid signature" });
  }

  const event = JSON.parse(req.body.toString());
  // handle event ...
  res.status(200).send("ok");
});
```

### Python

```python
import hashlib
import hmac
import os
from flask import Flask, request, abort

app = Flask(__name__)
WEBHOOK_SECRET = os.environ["NEXCORE_WEBHOOK_SECRET"].encode()

def verify_signature(raw_body: bytes, signature: str) -> bool:
    expected = hmac.new(WEBHOOK_SECRET, raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)

@app.post("/hooks/nexcore")
def handle_webhook():
    signature = request.headers.get("X-NexCore-Signature", "")
    if not verify_signature(request.get_data(), signature):
        abort(401)

    event = request.get_json()
    # handle event ...
    return "", 200
```

## Retry Logic

If your endpoint returns a non-2xx HTTP status code, or does not respond within **30 seconds**, NexCore treats the delivery as failed and schedules a retry using exponential backoff:

| Attempt | Delay after previous failure |
|---|---|
| 1st retry | 5 seconds |
| 2nd retry | 30 seconds |
| 3rd retry | 5 minutes |
| 4th retry | 30 minutes |
| 5th retry | 2 hours |

After **5 failed retries** (6 total attempts), the delivery is moved to the **dead-letter queue**. You can inspect and manually replay dead-letter events from **Dashboard → Webhooks → Logs → Dead Letter**.

<Tip>
Return an HTTP `200` response as quickly as possible — ideally before you begin processing the event — and hand the work off to a background queue or async task. This prevents your processing time from accidentally triggering a timeout and causing unnecessary retries.
</Tip>

## Webhook Logs

NexCore keeps a 30-day delivery history for every webhook. To review it, navigate to **Dashboard → Webhooks → Logs**. Each log entry shows:

- **Delivery ID** — unique identifier for the specific delivery attempt.
- **Event ID** — the `id` field from the payload, useful for correlation.
- **Attempt** — which attempt number this was (1–6).
- **Status** — `success`, `failed`, or `pending`.
- **HTTP Status Code** — the response code your endpoint returned.
- **Duration** — round-trip time for the delivery in milliseconds.
- **Response Body** — the first 1 KB of your endpoint's response, useful for debugging.

You can click **Replay** on any log entry to immediately re-deliver that event to your endpoint, regardless of its original status.

## Testing Webhooks Locally

Your local development server is not publicly reachable by default, so you need a tunnelling tool to expose it to NexCore during development.

### Using ngrok

```bash
# Install ngrok from https://ngrok.com, then:
ngrok http 3000
```

ngrok prints a public HTTPS URL such as `https://a1b2c3d4.ngrok-free.app`. Paste that URL (with your route appended) into the NexCore **Endpoint URL** field when creating or editing a webhook.

### Using localtunnel

```bash
# Install localtunnel globally
npm install -g localtunnel

# Expose port 3000
lt --port 3000 --subdomain my-nexcore-test
# → your URL: https://my-nexcore-test.loca.lt
```

Remember to update the webhook endpoint URL in the dashboard each time you start a new tunnel session, as temporary subdomains change between sessions.

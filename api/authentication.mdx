Every request to the NexCore API must be authenticated. Authentication is performed by passing your API key as a Bearer token in the `Authorization` header of each HTTP request. There are no session cookies or login flows — each request is independently authorized using the key you provide.

## Header Format

Include your API key in the `Authorization` header using the `Bearer` scheme:

```text
Authorization: Bearer nxc_live_xxxxxxxxxxxxxx
```

This header is required on **every** API request, including GET requests. Requests made without a valid `Authorization` header will receive a `401 Unauthorized` response.

## Obtaining an API Key

API keys are scoped to individual projects. To create a key:

<Steps>
  <Step title="Open the Dashboard">
    Navigate to the [NexCore Dashboard](https://app.nexcore.io) and sign in to your account.
  </Step>
  <Step title="Select your project">
    Choose the **Project** you want to integrate with from the project list.
  </Step>
  <Step title="Go to API Keys">
    Navigate to **Settings** → **API Keys** within the selected project.
  </Step>
  <Step title="Create your key">
    Click **Create Key**, choose a name and permission scope, then confirm. Your key is shown **once** immediately after creation — copy it to a secure location before closing the screen.
  </Step>
</Steps>

<Warning>
  You cannot retrieve the full key value again after leaving the creation screen. If you lose a key, revoke it immediately from the Dashboard and create a new one.
</Warning>

## Key Formats

NexCore issues two types of API keys, distinguished by their prefix:

| Prefix | Environment | Description |
|---|---|---|
| `nxc_live_` | Production | Affects live data and real billing. Use in your production environment only. |
| `nxc_test_` | Sandbox | Safe for development and testing. Events and resources created with test keys are isolated from production. |

<Tip>
  Use `nxc_test_` keys in all development and staging environments. Test keys behave identically to live keys at the API level but do not trigger production side effects such as downstream webhook delivery or billable event ingestion.
</Tip>

## Curl Example

The following example retrieves a list of projects using a live API key:

```bash
curl -X GET https://api.nexcore.io/v1/projects \
  -H "Authorization: Bearer nxc_live_xxxxxxxxxxxxxx" \
  -H "Content-Type: application/json"
```

Replace `nxc_live_xxxxxxxxxxxxxx` with your actual API key. For POST requests, add a `-d` flag with your JSON body.

## SDK Initialization

If you are using the official NexCore TypeScript SDK, pass your API key during client initialization. The SDK automatically attaches it as a Bearer token on every request:

```typescript
import { NexCore } from '@nexcore/sdk';

const client = new NexCore({ apiKey: process.env.NEXCORE_API_KEY });
```

Store your API key in an environment variable (e.g., `NEXCORE_API_KEY`) and load it at runtime. Never hard-code key values directly in your source code.

<Warning>
  Never embed API keys in client-side code, mobile app bundles, or public repositories. API keys grant full programmatic access to your project — exposing them publicly can lead to unauthorized usage and data loss. If a key is ever compromised, revoke it immediately from the Dashboard and rotate to a new one.
</Warning>

## Authentication Errors

When authentication fails, the API returns one of the following error responses:

| HTTP Status | Error Code | Cause |
|---|---|---|
| `401 Unauthorized` | `UNAUTHORIZED` | The `Authorization` header is missing, malformed, or contains an invalid API key. |
| `403 Forbidden` | `FORBIDDEN` | The API key is valid, but it does not have sufficient scope to perform the requested action. |

**Example 401 response:**

```json
{
  "ok": false,
  "error": {
    "code": "UNAUTHORIZED",
    "message": "Missing or invalid API key.",
    "details": {},
    "requestId": "req_01HZXXXXX"
  }
}
```

If you receive a `403`, open the Dashboard and verify that the API key you are using was created with the required permission scope (e.g., `write` for POST operations). You may need to create a new key with broader permissions.

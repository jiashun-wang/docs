NexCore follows semantic versioning. Breaking changes are announced **30 days in advance** via email to all project owners and are flagged with a `BREAKING` label in this changelog. Patch releases (`2.x.y`) are backward-compatible bug fixes and are deployed automatically. Minor releases (`2.x.0`) add new features and are also backward-compatible. Major releases (`x.0.0`) may contain breaking changes.

Subscribe to release notifications under **Settings → Notifications → Platform Updates** to receive an email for every new release.

## v2.4.0 — September 1, 2024

**AI Anomaly Detection · Prometheus Metrics Endpoint · Sensitivity Tuning**

### New Features

**AI Anomaly Detection — Generally Available**

AI-powered anomaly detection is now GA for all Pro, Growth, and Enterprise plans. After a 24-hour baseline learning period, NexCore automatically surfaces unusual patterns in your event streams — volume spikes, latency outliers, and unexpected field value distributions — directly in the dashboard under **Metrics → Anomalies**.

Configure detection sensitivity per stream using the new `sensitivity` parameter (values: `low`, `medium`, `high`; default `medium`):

```bash
curl -X PATCH https://api.nexcore.io/v1/streams/payments \
  -H "Authorization: Bearer $NEXCORE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "anomaly_detection": { "enabled": true, "sensitivity": "high" } }'
```

Higher sensitivity catches more subtle anomalies but may produce more false positives. Start with `medium` and adjust based on your alert noise.

**Prometheus Metrics Endpoint**

A Prometheus-compatible scrape endpoint is now available at `GET /v1/metrics/prometheus`. See the [Monitoring guide](/guides/monitoring#exporting-metrics) for configuration details and the full list of exposed metrics.

### Improvements

- Pipeline step execution logs now include per-step CPU and memory usage, making it easier to diagnose plugins approaching sandbox limits.
- The `nexcore dev` local development server now supports hot-reloading — plugin changes are applied automatically without restarting the dev session.
- Consumer group rebalancing time reduced by 40% for groups with more than 50 members.

### Bug Fixes

- Fixed an edge case where a dead-letter queue could receive duplicate events during a partition rebalance.
- Fixed dashboard chart rendering for streams with more than 1,000 partitions.

## v2.3.0 — August 1, 2024

**Custom Plugin SDK v2 · Pipeline Step Versioning · Consumer Group Improvements**

### New Features

**Custom Plugin SDK v2**

`@nexcore/plugin-sdk` v2.0.0 is now available. Key additions:

- New `PluginContext` object passed to `execute` exposes runtime config values, a structured logger (`ctx.log.info(...)`), and a `ctx.metrics` object for emitting custom metrics from within a plugin.
- Connector plugins can now declare output schemas, enabling NexCore to validate connector output against a schema before forwarding to the next step.
- TypeScript strict mode is now enforced by default in the SDK scaffold.

Migrate from v1 by updating `@nexcore/plugin-sdk` to `^2.0.0` and adding the `ctx` parameter to your `execute` function signature. The v1 signature remains supported until v3.0.0.

**Pipeline Step Versioning**

Individual pipeline steps can now be pinned to a specific plugin version, independent of the plugin's promoted version. This allows you to test a new plugin version on one step of a pipeline without affecting other pipelines that reference the same plugin.

**Consumer Group Improvements**

- Consumer groups now support a `sessionTimeout` configuration parameter (default: 30 seconds). Consumers that do not send a heartbeat within the session timeout are considered failed and their partitions are reassigned.
- Added `GET /v1/streams/{stream}/consumer-groups` API endpoint to list all groups and their current lag.

### Improvements

- Schema Registry now supports Avro with schema references (nested type definitions).
- Bulk event export (CSV format) is now available in addition to NDJSON.

### Bug Fixes

- Fixed a memory leak in the TypeScript SDK's WebSocket consumer when `reconnect` was enabled and the connection was intentionally closed.
- Fixed incorrect `consumer_lag_seconds` metric when a consumer group had never committed an offset.

## v2.2.0 — July 1, 2024

**Multi-Region Support · Audit Logs API · Slack Alert Integration**

### New Features

**Multi-Region Support: ap-southeast-1**

NexCore is now available in Singapore (`ap-southeast-1`), joining `us-east-1` and `eu-west-1`. Select your region at project creation time. Data never leaves the selected region.

Regional API endpoint: `api.ap-southeast-1.nexcore.io`

**Audit Logs API**

All administrative actions — stream creation and deletion, pipeline changes, API key management, member invitations — are now recorded in the Audit Log and accessible via the API:

```bash
curl "https://api.nexcore.io/v1/audit-logs?from=2024-07-01T00:00:00Z&to=2024-07-31T23:59:59Z" \
  -H "Authorization: Bearer $NEXCORE_API_KEY"
```

Audit logs are retained for 1 year and are available on Pro, Growth, and Enterprise plans.

**Slack Alert Integration**

Alerts can now be delivered to Slack channels natively. Configure your Slack workspace webhook URL under **Settings → Notification Channels → Add Channel → Slack**. Alert messages include the metric name, current value, threshold, and a one-click link to the relevant dashboard view.

### Improvements

- Stream creation time reduced from ~3 seconds to under 500ms.
- Dashboard now shows a real-time event counter (updates every 2 seconds) on the stream list page.

### Bug Fixes

- Fixed Metrics API returning incorrect `latency_p99_ms` values for streams with very low event volume.
- Fixed a permissions issue where project viewers could access the Audit Logs page in the dashboard (API access was already correctly restricted).

## v2.1.0 — June 1, 2024

**WebSocket Reconnection · Python SDK · 50% p99 Latency Reduction**

### New Features

**Improved WebSocket Reconnection**

The SDK's WebSocket consumer now uses a smarter reconnection strategy: on disconnect, it resumes from the last successfully acknowledged offset rather than the last received offset. This eliminates duplicate event processing after brief disconnects. The reconnection window is configurable:

```typescript
const consumer = client.stream.consume('orders', {
  reconnect: {
    maxAttempts: 20,
    backoffMs: 500,
    maxBackoffMs: 30000
  }
});
```

**Python SDK — Generally Available**

The official NexCore Python SDK is now GA:

```bash
pip install nexcore-sdk
```

The Python SDK supports all core operations: emitting events, consuming streams with consumer groups, managing streams and pipelines, and querying the Metrics API. Full documentation is available in the [SDK Setup guide](/guides/sdk-setup).

### Improvements

**50% Reduction in p99 Latency**

Internal pipeline processing infrastructure was rewritten to reduce the p99 end-to-end latency from an average of 12ms to 6ms for single-step pipelines. Multi-step pipelines see proportional improvements.

- Upgraded the underlying stream storage engine to reduce read amplification on high-partition streams.
- Improved partition leader election speed after node failures — failover time reduced from ~10 seconds to under 2 seconds.

## v2.0.0 — May 1, 2024

**Pipeline Builder GA · New RBAC System**

### New Features

**Pipeline Builder — Generally Available**

The visual pipeline builder exits beta and is now GA. Build, test, and deploy event processing pipelines without writing infrastructure code. The builder supports all native step types (filter, transform, aggregate, branch, connector) and custom plugin steps.

**New RBAC System**

Project-level roles have been redesigned for finer-grained access control. The new roles are:

| Role    | Permissions |
|---------|-------------|
| Owner   | Full access including billing and member management |
| Admin   | Full access excluding billing |
| Developer | Create and manage streams, pipelines, and plugins; no member management |
| Analyst | Read-only dashboard and Metrics API access |
| Viewer  | Dashboard read-only |

Existing members are migrated to the nearest equivalent new role. Review your team's roles under **Settings → Members** after upgrading.

### Breaking Changes

<Warning>
  **v2.0.0 contains a breaking API change.** The event ingest endpoint has been renamed from `POST /v1/emit` to `POST /v1/events`. The old `/v1/emit` endpoint will return `410 Gone` as of **June 1, 2024** (30 days after this release).

  Update all producers to use the new endpoint before that date. The request and response body schemas are unchanged — only the URL path has changed.

  ```bash
  # Old (deprecated — remove before June 1, 2024)
  POST https://api.nexcore.io/v1/emit

  # New
  POST https://api.nexcore.io/v1/events
  ```
</Warning>

### Improvements

- NexCore CLI (`nexcore`) is now available for Linux, macOS, and Windows. Install via `npm install -g @nexcore/cli`.
- Stream and pipeline names now support hyphens and underscores (previously letters and numbers only).

### Bug Fixes

- Fixed a race condition that could cause events to be delivered twice during a stream partition rebalance in rare circumstances.
- Fixed the dashboard showing incorrect member counts for projects with more than 100 members.
